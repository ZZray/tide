# v0.1.1 修复与自动更新 / Fixes and in-app updates

日期 / Date: 2026-10-22。发布提交与 tag：`453e307`（`v0.1.1`）。关联：[发布说明](../releases/v0.1.1.md)、[开发文档](../development.md#in-app-updates--应用内更新)。

## 范围

v0.1.0 便携版命令行实测（临时目录、本地裸仓库、双端）发现三个问题，本版修复，并加入 GitHub Releases 自动更新。

| 问题 | 根因 | 修复 |
|---|---|---|
| 同步结果 `changed` 在首次下载、快进时为 0 | 只在“逐文件对账”分支累加 | 推送成功后统一按“本轮前本地文件集 → 推送目标”计 `changed`，“远端 tip → 目标”计新增的 `uploaded` |
| `tide diff` 中文路径显示 `\344…` | libgit2 文件头按 `core.quotepath` 规则 C 转义非 ASCII 路径 | 打印时解码 'F' 文件头里的引号路径 |
| 远端覆盖本地把被替换的本地版本推到远端 | 替换提交的父提交包含本地快照 | HEAD 直接采用远端提交；本地快照只保存在 `refs/tide/replaced/*`，历史里标“仅保存在本机”可恢复；远端为空时拒绝 |

自动更新设计要点：

- 版本来源用 `releases.atom`，不用 REST API。实测本机经代理访问匿名 API 已返回 403 rate limit。
- 资产按固定命名下载，必须与同一发布的 `SHA256SUMS.txt` 一致。启动安装前再校验一次。
- 安装版判定：可执行文件旁有 `unins000.exe`。便携版只提示新版本。
- 用户点“重启以更新”后：事件循环结束 → 等待同步服务停止 → 以 `/VERYSILENT … /RELAUNCH=window|background /WAITPID=<pid>` 启动安装程序 → `.iss` 等待原进程退出后安装并重新打开。
- 检查失败（离线、代理）1 小时后重试；下载或校验失败等下一次每日或手动检查。

## 已知限制与未验证项

- 来源可信度：校验文件与安装包来自同一发布，只防损坏和传输替换，不防能发布 Release 的人；安装包未代码签名。
- 托盘菜单“重启以更新”、后台（`/RELAUNCH=background`）重启、更新时有长时间同步在进行的情况：代码已审查，未实测。
- 重试路径上若用户在同步中途编辑文件，`changed` 会把这些编辑算进去（计数偏差，不影响数据）。
- Slint 构建未启用无障碍接口，UI Automation 读不到控件；如需自动化界面测试需另行开启。
- 发布 Release 后，任何改名资产、漏传 `SHA256SUMS.txt` 或对已发布 tag 换资产，都会让已安装用户无法更新。
