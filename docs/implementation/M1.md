# M1 实现分析与交付

日期：2026-10-18。依据：[原始设计](../specs/2026-10-18_Tide设计.md)。

此文是 M1 时点的历史记录。桌面、热加载、类型化状态和真实远端验收的后续实现见 [M2](M2.md)，下文“尚未实现”不代表最新状态。

本次把空代码仓库推进到可运行、可测试的命令行预览版。当前范围是 M1 引擎，加上可独立使用的监听/调度、历史和覆盖操作；不是 M2–M4 桌面产品已经完成。

## 设计分析

1. **先验证字节和历史，再接桌面界面。** `tide-git` 负责 libgit2 与工作区，`tide-core` 负责配置、运行记录和调度，`tide-app` 提供 CLI。引擎不依赖 Slint 或 WebView。
2. **Git 的三方内容合并不等于工作区安全写回。** 使用内存文件树对账；文本仅对白名单中的 UTF-8、无 NUL 文件执行三方合并，合并失败的带标记结果不写入工作区。二进制和重叠修改进入配置的冲突策略。
3. **写回和 HEAD 更新必须有恢复路径。** 先保留目标提交到 `refs/tide/pending`，持久化写回记录，再按文件核对哈希、写临时文件、替换。索引和分支更新后清理记录。重开仓库可继续，出现新编辑则停止；`recover` 保存当前内容，并把原目标保留为祖先。
4. **“两份都保留”是内容策略，历史还要保留双方父提交。** 合并提交包含远端与本地父提交；覆盖、恢复都追加提交，无 rebase、无 force push。远端覆盖本地另保留 `refs/tide/replaced/*`。
5. **现有 Git 状态不能被静默接管。** 暂存改动、冲突、合并/rebase、分支不匹配和 `index.lock` 都阻止同步。外置元数据不会自动迁移已有历史。
6. **人工选择需要落盘。** Ask 策略保存候选合并提交和冲突清单。命令行阶段暂停该文件夹这一轮，解决所有冲突后再同步；原始设计的“同文件夹其他文件继续同步”留到后续阶段。

## 当前能力

| 部分 | 实现 |
|---|---|
| 工程 | Rust 三 crate workspace、Cargo.lock、静态 libgit2、Windows 静态 CRT |
| 配置 | TOML、原子保存、配置锁、文件夹 CRUD、暂停/继续、路径重复和嵌套检查、外置 Git 目录 |
| 首次关联 | 空远端上传、空本地下载、已有分支接管、独立历史必须显式确认且强制两份保留 |
| 同步预览 | `plan` 检查连接、两端文件数和体积、同名不同内容；不提交、不推送、不修改文档 |
| 认证 | SSH agent、显式私钥路径、HTTPS Git 凭据助手；不存令牌，不绕过 TLS 校验 |
| 同步 | 本地快照、fetch、merge-base、逐文件对账、快进、文本合并、非快进推送最多三次重试 |
| 冲突 | keep_both / prefer_local / prefer_remote / ask；冲突副本防重名、设备名清洗 |
| 文件 | 原样 blob 写入，保留 CRLF/二进制字节；默认忽略规则、2 秒稳定窗口、大小阈值 |
| 护栏 | 根目录丢失和大量删除停止远端修改并持久暂停；Git 仓库锁避免两个 Tide 同时写入 |
| 历史 | 50 条分页、设备/时间/改动数、文本 diff、文件导出、单文件/整树恢复 |
| 覆盖 | 本地内容追加提交后推送；远端内容恢复到本地，旧内容仍可从历史恢复 |
| 调度 | 最多两工作线程；OS 文件事件；防抖最多顺延 5 分钟；启动延迟 10 秒；失败 1–30 分钟退避；重复触发合并 |
| 记录 | JSONL 每轮结果、运行 ID、耗时、冲突和镜像失败；最多保留 1000 轮 |

命令和完整配置见 [README](../../README.md) 与 [配置示例](../../examples/config.toml)。配置键以示例为准，原设计的 UI/通知/钥匙串设置尚未接入，未知配置键会明确报错。

## 已验证与验证方法

测试使用临时本地裸仓库，两个独立工作区模拟两台设备，不使用 mock Git，不接触用户远端。

- 对账：单端新增/修改/删除、双端相同修改、不重叠文本合并、同名新增、二进制冲突、两种删改方向。
- 四种冲突策略；多文件 Ask 选择本地后仍保留远端新增文件；冲突状态重开后可恢复。
- CRLF、NUL、非 UTF-8 文件内容和中文路径按字节保留；已有冲突副本不覆盖。
- 根目录缺失、删除护栏、暂存改动、`index.lock`、两 Tide 争用、超限和仍在写入的文件。
- 外置历史目录、忽略规则、缺失远端分支、镜像失败不影响主远端成功。
- 模拟 fetch 后远端前进；连续三次推送拒绝时不移动 `refs/tide/synced`。
- 模拟部分文件已写回后进程重启；较新编辑阻止恢复覆盖，`recover` 保留编辑和原目标。
- 恢复、覆盖、分页、diff、导出不覆盖目标文件；路径穿越、远端符号链接和大小写冲突被拒绝。
- CLI 完整生命周期、非零错误退出码；启动真实 `watch` 子进程，由 OS 文件事件触发实际推送。
- 双工作区交替修改 1000 轮：每轮比对两端内容，并验证远端新提交可追溯到前一轮。

验证命令：

```powershell
.\scripts\dev.ps1 fmt --all --check
.\scripts\dev.ps1 clippy --workspace --all-targets '--' -D warnings
.\scripts\dev.ps1 test --workspace
.\scripts\dev.ps1 build --release --workspace --locked
```

本机工具链：Windows x64、Rust 1.99.1、MSVC 14.50、git2 0.21.0 / libgit2 1.9.7。git2 0.20.4 的 `remote.list()` 在空远端上触发新 Rust 的空指针检查，升级至 0.21 后修复；该版本的 SSH/HTTPS 特性需要显式开启。

三平台 CI 已配置，但本地验证不代表 macOS/Linux 或真实 GitHub/Gitee 的 SSH/HTTPS 验收。CLI 大小、DLL 依赖和最终检查结果见下方验收记录；原设计的托盘内存、UI 内存和 1 万文件性能目标仍未测量。

## 当前限制与后续工作

- **桌面外壳未实现。** 没有 Slint 主窗口、向导、托盘、主题、通知、开机启动、系统钥匙串或签名安装包；HTML 是原设计样机。接 Slint 前仍需核对其桌面授权与署名条款。
- **监听配置要重启加载。** 另一进程修改配置后，已运行的 `watch` 需重启；不提供跨进程立即暂停和唤起窗口。断电测试采用持久记录模拟，没有进行实际断电试验；系统睡眠唤醒专用事件尚未接入。
- **保守停止。** 不稳定、占用、过大或不支持的文件阻止当前轮，未做到跳过该文件继续其他文件；认证等错误通过已保留的错误文本分类停止重试，后续应引入类型化错误和阶段事件。Ask 暂停整个文件夹这一轮。
- **文件系统边界。** 不支持 LFS、符号链接/目录 junction、子模块、非 UTF-8 文件名、Windows 保留文件名、大小写重名；文件/目录互换可能需要人工整理。已跟踪文件不会因新增 ignore 规则自动从历史中删除。
- **并发写入边界。** 内容哈希核对避免覆盖可观测到的新编辑，但跨应用的最后一次核对与原子替换之间仍有操作系统竞争窗口；不宣称对任意编辑器并发写入提供绝对无丢失保证。也不应与 Git 命令行写操作并行使用。
- **资源和平台待验。** 没有预检磁盘剩余空间、网络超时/取消 UI、真实远端测试或原设计资源指标实测。网络调用使用 libgit2 超时行为；SSH 加密私钥应通过 agent 解锁。凭据助手需要已配置的外部 helper，尚未内置 keyring。
- **记录尚无完整事件流。** 当前保留每轮结果；逐阶段英文滚动日志、开始/结束成对事件、七天清理留待桌面阶段。`changed` 是合并写回计数，尚不是完整上传/下载统计。
- **覆盖默认不强推。** 镜像落后且为同一历史时可快进，镜像有独立历史会报告失败；不会覆盖备份分支。`overwrite remote` 仅生成本地恢复提交，之后 `sync` 才发布。

建议后续顺序：类型化同步状态/阶段事件与配置热加载 → Slint 主窗口和添加向导 → 托盘/凭据/系统集成 → 三平台真实远端验收与资源实测/打包。桌面界面应消费现有引擎，不复制同步算法。
