Tide：基于 Git 的轻量文档同步

一个常驻托盘的小程序。你指定几个本地文件夹，它把每个文件夹接到一个 Git 远端上，定时或在改动后自动同步，所有版本都留在历史里，覆盖和回滚都能撤销。

目标与边界

要做
  • 多个同步文件夹，每个的本地位置、远端、分支、规则都可自定义
  • 定时同步、改动后自动同步、立即同步（单个或全部）
  • 增量：只扫改动文件，只传差异对象
  • 历史：按时间和设备浏览，查看差异，恢复单个文件或整个文件夹
  • 覆盖：本地覆盖远端、远端覆盖本地，均可撤销
  • 同步文件夹的增删改查；托盘常驻；深色界面（跟随系统 / 浅 / 深）
不做
  • 不做通用 Git 客户端：没有分支管理、暂存区、交互式 diff 编辑
  • 不做实时协同编辑，不做移动端
  • 不自建服务器，任何 Git 远端都行（GitHub、Gitee、自建 Gitea、NAS 上的裸仓库）
  • 首版不支持 Git LFS（见待拍板）

技术选型

界面框架

按“纯 Rust、占用小、看起来现代”三条筛。内存量级是同类应用的经验估计，不是本项目实测。

方案语言常驻内存量级观感结论
SlintRust + .slint 声明式低，十几到几十 MB自带 Fluent 深色样式，可完全自绘推荐

egui纯 Rust，即时模式低工具感强，难做精致只适合调试面板

Avalonia（.NET NativeAOT）C#中高Fluent 成熟团队更想写 C# 时再考虑
为什么是 Slint

.slint 的写法和 QML 很像（属性绑定、组件、状态），Slint 团队也是 Qt 出身，你们团队上手成本最低。界面描述编译进二进制，不需要运行时解释。它的许可证对桌面应用有免版税条款，要求在“关于”里标注 Slint，正式开工前核对一次条款原文。

Git 引擎

方案情况结论
git2（libgit2，vendored 静态链接）clone、fetch、push、合并、文件级三方合并、SSH 和 HTTPS 都成熟；用户机器上不需要装 Git首版用它
gix（gitoxide，纯 Rust）读、status、fetch 很快；按我掌握的情况 push 还没完成。开工时再查一次进度藏在接口后，push 成熟后可替换
调用系统 git 命令兼容性最好（凭据助手、LFS），但依赖用户安装、要解析输出只作为可选后端，用于 LFS 等场景

诚实说明：libgit2 是 C 库，所以“纯 Rust”在 Git 这一层做不到 100%。它静态编进同一个可执行文件，用户感知不到。引擎通过 GitBackend 接口调用，以后换 gix 不动上层。

线程模型
  • 主线程：Slint 事件循环；Windows、macOS 的托盘也在这里
  • 调度线程：维护每个文件夹的下次到期时间，睡到最近一个
  • 同步工作线程 ×2：执行同步，结果经通道回传，界面用 invoke_from_event_loop 刷新

文件夹与自定义位置

“同步文件夹”是唯一的核心对象，界面上的增删改查都围绕它。数量不限，每个都可以单独设置下面这些。

项可选值默认
本地位置任意路径：其他盘符、移动硬盘、网络共享（网络共享会提示：别的电脑同时改可能出冲突）用户选
历史数据位置放文件夹里的 .git；或集中放到自定义目录，文件夹里不留任何隐藏目录文件夹内，搬文件夹时历史跟着走
远端SSH 或 HTTPS 地址；同一个远端仓库可以给多个本地文件夹用，各用一个分支—
备份远端零到多个，只推送不拉取，比如主用 GitHub、Gitee 做备份无
认证SSH 密钥 / 访问令牌 / 系统 Git 凭据助手按地址自动猜
同步时机每 5 / 15 / 30 / 60 分钟或自定义；改动后自动同步；启动时同步；只手动每 15 分钟 + 改动后
冲突策略两份都保留 / 本地优先 / 远端优先 / 每次问我两份都保留
忽略规则预设（Office 临时文件、系统文件）+ 自定义，写成 .gitignore 语法预设开启
大文件超过阈值提醒或不收录50 MB 提醒，100 MB 不收录

校验：同步文件夹不能互相嵌套；同一个本地路径不能加两次；同一远端同一分支被两个文件夹使用时给出提醒。

同步算法

对文档来说，最重要的是两件事：不丢任何一个版本，不往文档里写 <<<<<<< 冲突标记。所以不用 Git 的 rebase 或带冲突标记的 merge，而是按文件做三方对账，自己生成合并结果。

一轮同步（单个文件夹，持有该文件夹的锁）

  1. 收集：把工作区改动写入索引。只收修改时间已经稳定 2 秒的文件，避免收进写到一半的文档。有改动就提交本地快照 L，作者是设备名。
  2. 护栏：文件夹根目录不存在，或者这次要删除超过 50 个且超过 30% 的文件，立刻暂停这个文件夹并提示，不往下走。移动硬盘没插好时就不会把远端清空。
  3. 拉取：fetch 远端分支，得到 R。
  4. 对账：B = merge-base(L, R)。R = B 时直接推送；L = B 时快进到 R；两边都有新内容时按下表逐个文件决定，生成合并提交 M（父提交是 R 和 L，两边的版本都留在历史里）。
  5. 写回：只把内容变了的文件写回工作区，先写临时文件再改名。写之前核对哈希：如果用户这期间又改了这个文件，这一轮不覆盖它，下一轮重新对账。
  6. 推送：push 到远端，再推备份远端。远端拒绝（别的设备刚推过）就回到第 3 步，最多重试 3 次。
  7. 收尾：推送成功后才移动 refs/tide/synced 指针，写运行记录，刷新界面和托盘。中途断电或崩溃，下次启动从第 1 步重来即可，不需要修复。

覆盖与历史

原则：所有覆盖和恢复都是往前追加一个新提交，从不改写历史，从不 force push。因此每个操作都能撤销，界面上用“撤销”代替层层确认，只有真正删数据的操作才要求二次确认。

操作实际做什么怎么撤销
用本地覆盖远端在远端最新提交之上提交一个“内容 = 本地”的新提交并推送。其他设备下次同步就变成这份历史里恢复覆盖前那一刻
用远端覆盖本地先把本地没同步的改动存成快照 refs/tide/replaced/<时间>，再把文件夹变成远端最新内容历史 → 被替换的版本 → 恢复
恢复单个文件把这个文件改回选中的版本，作为一次普通改动同步出去再恢复一次
恢复整个文件夹到某一刻新提交，内容 = 那一刻的完整文件树同上
另存为把某个版本的文件导出到你选的位置，不影响同步—
移除同步文件夹默认只从 Tide 里移除，文件和历史都留在原处；勾选后才删除历史数据（.git 或集中目录），文档本身永远不删删除历史数据不可撤销，所以要二次确认

历史列表按时间倒序、按天分组，每条显示时间、来自哪台设备、改了几个文件。自动生成的合并提交默认折叠成一行“合并了 笔记本 的改动”，只有发生过冲突的合并才展开显示。列表每次加载 50 条，滚到底再取下一页。

状态含义

托盘图标取最严重的一个

出错 > 有冲突 > 同步中 > 有改动 > 离线 > 已暂停 > 已同步。图标只用角标颜色区分，具体原因写在悬停提示里，比如“读书笔记：GitHub 拒绝了访问令牌”。

调度规则

  • 每个文件夹有自己的下次到期时间；调度线程睡到最近一个
  • 文件改动：防抖 30 秒后触发，连续改动会顺延，但最多顺延到 5 分钟
  • 程序启动 10 秒后、电脑从睡眠唤醒后，各跑一轮
  • 失败退避：1、2、4、8 分钟……最长 30 分钟；认证失败不自动重试，等你更新凭据
  • 正在同步时再点“立即同步”：记一个“结束后再来一轮”，不重复排队

日志

每轮同步一个 run_id，开始和结束成对记录，带耗时；失败记录阶段和原因。运行记录同时写入 runs.jsonl（保留最近 1000 轮），界面的“同步记录”就读它。

文案

语气平实，说清现在怎样、接下来会怎样、用户要不要做什么。出错时写原因和出路，不卖萌。

场景文案
托盘悬停（一切正常）全部同步好了 · 14:30
离线现在连不上 github.com。改动都存在本地，联网后会自动补上。
认证失败GitHub 拒绝了访问令牌，可能已经过期。更新凭据后会马上重试。
冲突（两份都保留）书单.md 在两台电脑上都改过。两份都留下了：远端版本在原位，你这台的在“书单 (冲突 · 笔记本 · 10-18 14.30).md”。
文件被占用读书会议程.docx 正在被 Word 使用，关掉后下一轮会同步。
找不到文件夹找不到 E:\合同扫描件，可能是移动硬盘没插。已暂停，插上后点“继续同步”。
首次同步完成（只出现一次）第一次同步完成，128 个文件已经在远端了。之后的改动会自己跟上。
巧思落在哪
  • 历史和冲突副本都带设备名，多台电脑来回改时，一眼知道“这是哪台改的”。
  • 状态栏写“14:45 自动同步”而不是只写“有改动”，用户不必猜要不要手动点。
  • 离线时强调“改动都在本地”，让人放心合上笔记本。
  • 护栏弹窗先说“远端没有任何变化”，再说可能原因，用户最担心的事放在第一句。
  • 只有首次同步完成有一句温和的完成提示；之后每次成功都保持安静，不打扰。

异常处理

情况处理用户看到
网络不通、超时进入“离线”，按退避重试；离线是笔记本的常态，不弹通知托盘灰色，悬停写原因
认证失败停止自动重试，等用户更新凭据通知一次 +“更新凭据”按钮
推送被拒（别的设备刚推过）重新拉取、对账、推送，最多 3 次3 次都失败才提示“远端改动太频繁，稍后再试”
远端仓库或分支不存在出错并暂停引导重新填远端，或在远端新建分支
文件被占用（Windows 共享冲突）跳过这个文件，其余照常改动列表里标“占用”
文件正在写入修改时间稳定 2 秒才收录无感
本地文件夹不见了暂停，绝不当作“全部删除”“找不到文件夹”+ 继续同步按钮
大量删除护栏暂停（> 50 个且 > 30%）护栏弹窗
大文件超提醒阈值提示；超上限不收录，写进忽略清单改动列表标“太大，未同步”
磁盘满写回前检查剩余空间，不够就不写出错，写明需要多少空间
用户自己也在用 git 命令行发现 index.lock 就跳过这一轮；超过 10 分钟仍在且没有 git 进程，提示清理同步记录里写明跳过原因
同步中途崩溃或断电同步指针只在推送成功后移动，重启后重新对账无感
第二次启动程序单实例，唤起已运行的窗口窗口出现在前面

验证与里程碑

怎么测

  • 引擎集成测试：临时目录里建一个裸仓库当远端，克隆出 A、B 两个工作区当两台设备，用真实 Git 跑，不用 mock。覆盖对账表每一行、三种冲突策略、冲突副本命名、护栏、文件夹消失、推送被拒重试、崩溃后重新对账。
  • 监听与调度：防抖、顺延上限、退避、休眠唤醒补跑，用可注入的时钟测。
  • 界面：Slint 测试后端测视图模型与状态映射；交互和视觉人工走查，亮暗两套都看。
  • 真实远端：GitHub、Gitee 的 SSH 和 HTTPS，用环境变量 REAL_REMOTE=1 打开，默认 CI 跳过。
  • 资源：托盘常驻 10 分钟后量工作集和私有内存，三个平台各测一次，结果回填上面的资源目标表。

里程碑

阶段交付完成标准
M1 引擎tide-core、tide-git，开发用命令行入口对账表全部用例通过；两个工作区来回改 1000 轮不丢版本

M3 历史与覆盖历史、差异、恢复、覆盖、冲突页所有覆盖操作都能在历史里撤销
M4 打包Windows 安装包（代码签名）、macOS dmg（公证）、Linux AppImage / deb；开机启动资源实测达标，或给出差距和原因

待拍板

  1. 要不要支持 Git LFS：如果同步的文档里大 PDF、扫描件多，仓库会膨胀得很快。libgit2 不支持 LFS，要支持就得为这类文件夹切到“系统 git”后端。
  2. 冲突默认策略：建议“两份都保留”，最安全，代价是偶尔多一个副本文件要手动删。
  3. Linux 是否首发：Linux 托盘依赖桌面环境（GNOME 需要扩展才显示托盘），可以放到 M4 之后。
  4. 名字：Tide 是暂定名。
